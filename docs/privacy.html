Política de privacidade

Atualizada em 4 de novembro de 2026.

Esta política descreve o tratamento de dados pelo Password Keeper, aplicativo de cofre de senhas para desktop e Android mantido no projeto Praesens-tech/passwordKeeper. Contato do desenvolvedor: mpblima@gmail.com.

1. Cofre e armazenamento local

As informações inseridas no cofre são processadas no dispositivo. O aplicativo criptografa o conteúdo com AES-256-GCM antes de gravá-lo em arquivos .keep, enviá-lo ao Google Drive como sincronização opcional do cofre pessoal ou salvá-lo no Firestore para compartilhamento. A senha mestra é usada no dispositivo para derivar a chave de criptografia e não é enviada ao Google, ao Firebase ou ao desenvolvedor. O conteúdo descriptografado permanece na memória durante o uso do cofre.

O dispositivo também armazena configurações, referências dos arquivos, informações da conta conectada e tokens OAuth usados para acessar o Drive. Os tokens são persistidos no armazenamento de configuração do aplicativo, separados do cofre, e não no localStorage do WebView. Esses tokens permitem acesso às APIs autorizadas e devem ser protegidos junto com o dispositivo.

2. Dados do Google e finalidade do acesso

A conexão ao Google é opcional. Ao conectar uma conta, o aplicativo usa o endereço de e-mail e os dados de perfil disponibilizados pela API para identificar a conta conectada e a autoria dos compartilhamentos. Usa tokens de acesso e de renovação para autenticar as solicitações e manter a sincronização autorizada.

A versão atual solicita o escopo https://www.googleapis.com/auth/drive, que tecnicamente permite acesso amplo aos arquivos do Drive. No funcionamento do Password Keeper, esse acesso é usado para localizar, ler e atualizar o arquivo criptografado do cofre pessoal e detectar alterações para sincronização. O aplicativo não cria nem lê arquivos de compartilhamento ou permissões de colaboração no Drive. O escopo https://www.googleapis.com/auth/userinfo.email é usado para identificar a conta. A autenticação Google também fornece ao Firebase a identidade necessária para controlar o acesso aos compartilhamentos.

As solicitações às APIs do Google são feitas pelo aplicativo no dispositivo. O aplicativo envia envelopes cifrados e metadados de acesso ao Firebase/Firestore para compartilhar cofres, grupos ou senhas. O Firebase também processa a identidade autenticada. O Google recebe solicitações à sua API e armazena os arquivos criptografados do cofre pessoal, nomes e metadados no Drive da conta correspondente.

3. Compartilhamento

Ao solicitar um compartilhamento, o aplicativo envia ao Firebase o ciphertext do escopo autorizado, o e-mail do proprietário, o e-mail do destinatário e a permissão escolhida. O conteúdo é criptografado no dispositivo em um documento separado com AES-256-GCM. A senha mestra do cofre principal não é compartilhada; uma senha de compartilhamento separada é necessária para abrir o documento. O destinatário precisa entrar no app com o e-mail Google autorizado e fornecer essa senha. O Firestore armazena o documento cifrado e os e-mails necessários para controlar o acesso; não recebe o conteúdo em texto claro nem a senha de compartilhamento.

O desenvolvedor não recebe automaticamente acesso aos cofres. O uso dos dados obtidos das APIs do Google é limitado às funcionalidades de cofre, identidade, sincronização e colaboração descritas nesta política; esses dados não são vendidos, usados para publicidade personalizada ou para treinamento de modelos de inteligência artificial de uso geral.

4. Retenção, desconexão e exclusão

Os arquivos locais e no Drive permanecem nos locais escolhidos até serem removidos pelo usuário. O documento cifrado de compartilhamento permanece no Firestore até ser excluído pelo proprietário no Firebase Console. Remover um colaborador revoga o acesso dele, mas não apaga o documento. Desconectar a conta no aplicativo remove a referência local ao token e às informações da conta, mas não exclui automaticamente arquivos locais, backups, documentos do Firestore ou arquivos do Drive, nem revoga por si só a autorização no Google.

Para revogar o acesso Google, acesse as conexões da sua Conta do Google e remova o acesso do Password Keeper. O proprietário pode remover o acesso de um colaborador pelo app; para apagar permanentemente o documento cifrado, exclua-o no Firebase Console. Arquivos .keep e backups no Drive são removidos separadamente. No Drive, observe também a lixeira e as regras de retenção da sua conta. Excluir uma cópia não apaga cópias que destinatários já tenham exportado ou guardado.

5. Atualizações e site

O aplicativo pode consultar releases no GitHub para verificar atualizações e abrir links no navegador do sistema. O GitHub processa essas conexões conforme a sua política de privacidade; o conteúdo do cofre não faz parte da consulta de atualização.

Este site é hospedado no GitHub Pages e consulta contagens públicas de downloads das releases. O provedor de hospedagem e as APIs consultadas podem receber informações técnicas da conexão, como o endereço IP. O site não solicita o conteúdo do cofre ou a senha mestra.

6. Uso limitado dos dados do Google

O uso e a transferência de informações recebidas das APIs do Google pelo Password Keeper seguem a Política de Dados do Usuário dos Serviços de API do Google, incluindo os requisitos de Uso Limitado (Limited Use).

7. Contato e alterações

Para dúvidas sobre os dados tratados pelo aplicativo ou solicitações de privacidade, entre em contato pelo e-mail mpblima@gmail.com. Não envie senhas, tokens OAuth ou o conteúdo do seu cofre no pedido. Alterações nesta política serão publicadas nesta página com a data de atualização.
